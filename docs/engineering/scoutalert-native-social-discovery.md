## Search and evidence

- Only the confirmed public target enters a native query. Private location, background, account identity and full brief stay out of the API request. Mandatory requirements remain in personal matching. Queries currently combine the target with English demand phrases; multilingual strategies and richer alternative-role planning remain open.
- Identical public queries share one record across current scout subscriptions. Pause and revision checks apply before admission and again before dispatch. New subscribers can reuse recent captures without repeating a search.
- Recent search uses a fixed start/end window, initially one day, with the provider's continuation token. A successful final page advances coverage; partial responses, interruptions and failed leases do not. Subsequent windows overlap by one minute. If an outage exceeds the recent-search horizon, the query records a coverage gap. This is bounded recent search, not full-archive or whole-platform completeness.
- Each public post retains its native ID, author ID, publication time, conversation ID, edit identities and reference identities. Long-post text is requested. Replies/quotes with unfetched reference context remain incomplete and cannot publish as complete-source opportunities. Bounded parent, quote and conversation-root expansion is implemented; streaming remains outstanding.
- Native edit families reuse their first post ID as the canonical source URL. New X/Twitter handle URLs normalize to post URLs for deduplication. Pre-existing unnormalized rows and historical edit aliases can still undercount cross-provider overlap; no claim of complete historical identity reconciliation is made.
- Complete standalone posts and posts with complete bounded context enter the existing cited demand review and private fit pipeline. Missing organization, location, pay and application details stay unknown. Seller offers, discussions, inaccessible sources and incomplete context cannot become verified exceptional alerts. Existing consent, freshness and recipient delivery identities continue to apply.
- Native captures are refreshed through post lookup, independently of generic HTML monitoring. Explicit inaccessible IDs withdraw source content and derived recommendations; a post's absence from search does not establish deletion. Generic HTML fetches cannot overwrite an existing native capture.
- Retained native content expires after 24 hours without a new observation. Bounded maintenance sweeps clear the source body, public reviews, posting/evidence copies, private assessments and cached delivery content while retaining IDs and delivery audit. This maintenance continues with native access disabled. Already delivered email cannot be recalled. Production retention operations, request handling, display requirements and the intended X use case still need operational review before release.

## Admission and recovery

Native search and lookup use the `x-api` ledger, separate from Serper, document and AI allowances. Every request reserves its maximum returned-post allowance at the configured unit price. No user-profile expansions or hidden HTTP retries are made. Failed and ambiguous attempts remain charged; provider billing deduplication does not refund local reservations. Source review and personal assessment continue to use the existing shared AI budget.

The repository serializes native admission. Search, context lookup and post refresh share admission turns, with an oldest-due query turn reserved every fifth position. Native requests are now paced across the remaining UTC day after a three-request startup burst; query and post revisit intervals adapt to observed outcomes. See [scheduling and measurements](scoutalert-discovery-scheduling.md). Available classes can use otherwise idle capacity. Provider rate-reset headers and access failures pause the native provider without pausing Google discovery. Expired leases preserve cursor progress and defer another attempt. Increased configured budgets can admit waiting work without resetting usage. These are local operating controls, not demonstrated global fairness or throughput.

Native review recovery also checks the configured shared AI allowance. When admission is possible, maintenance requeues up to 500 unfinished associations from budget-deferred or expired review windows, then dispatches bounded cases for current active scout revisions. It also recovers cases superseded before review began, expired active windows and due transient failures. Active leases, terminal evidence failures, exhausted attempts, paused scouts and obsolete revisions cannot be requeued. The two-attempt ceiling and five-minute retry delay still apply. Published outbox receipts are required before recovering an abandoned case. Periodic full-search reconciliation allows recent native batches five minutes to begin and finish review, as it already did for monitored sources.

Recovery reuses still-retained native content without another X request and without advancing its observation time. Retained content older than the personal matching freshness window may be classified, but still needs a current source observation before matching or delivery. Historical deferred cases and failed-attempt receipts remain audit records. New native batches cannot supersede an active public review window. `20261004-review-recovery` indexes source-version review lookup.

In ignored `apps/worker/.env`, supply an app-only `X_BEARER_TOKEN` and explicitly set `SCOUT_X_ENABLED=true` when metered access should run. Keep credentials out of source control and chat. Restart the worker to load configuration.

| Setting                  | Default | Meaning                                                           |
| ------------------------ | ------- | ----------------------------------------------------------------- |
| `SCOUT_X_ENABLED`        | `false` | Enables native metered reads; expiry maintenance stays active     |
| `SCOUT_X_DAILY_REQUESTS` | `20`    | Combined search and lookup attempts per UTC day                   |
| `SCOUT_X_DAILY_USD`      | `1`     | Conservative native reservation ceiling per UTC day               |
| `SCOUT_X_POST_USD`       | `0.005` | Reservation for each potentially returned post                    |
| `SCOUT_X_PAGE_SIZE`      | `10`    | Maximum posts per admitted page/lookup batch, configurable to 100 |

The checked X documentation lists post reads at $0.005 per returned resource. Confirm account pricing in the developer console before enabling access; local reservations are not invoices. [X pricing](https://docs.x.com/x-api/getting-started/pricing). The adapter follows the documented [recent-search pagination](https://docs.x.com/x-api/posts/search/integrate/paginate) and [post lookup](https://docs.x.com/x-api/posts/lookup/introduction) paths. Content handling also follows the [developer policy](https://docs.x.com/developer-terms/policy); this implementation record is not a claim of production approval.

## Bounded context increment — 3 October, 01:21 WAT

The native coordinator now follows source-declared parent, quote, repost and conversation-root IDs. Each searched root admits at most six related posts across two reference levels; excerpts are limited to 2,000 UTF-8 bytes per related post. Context-only captures do not start another discovery frontier. Existing public captures are reused across current scout interests, and missing IDs share durable lookup requests. Provider lookups reserve their full returned-post allowance before HTTP, using the same X ledger and backoff as search. No implicit API expansions or hidden retries are used.

Primary text remains separate from related authors' text. The model receives each related post with identity, author, relation and source observation time. Instructions require classification of the primary author's intent, and citation validation only accepts primary-text passages as primary-post facts. A seller replying to a buyer cannot inherit the buyer's role or demand evidence. Related buyer requests can enter review independently. Native input keys include an attribution-policy version; ordinary web review reuse is unaffected. See [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) and [X post lookup](https://docs.x.com/x-api/posts/lookup/introduction).

Missing, inaccessible, cyclic, oversized or depth-limited context remains incomplete and cannot publish a complete-source opportunity. A complete packet means its bounded references were captured; it does not mean every conversation reply was read. The review's freshness is the oldest included observation, not context assembly time. The discovery view shows separate related-post links, author relationships, excerpts and incomplete-context notices.

Current dependencies and historical review inputs participate in invalidation. A referenced post edit, expiry or explicit unavailability removes dependent model results, evidence, recommendations and cached delivery content, fences in-flight reviews and schedules reconstruction. The original primary capture remains available if its own source is still valid. Freshly restored evidence can be reviewed again; a regression caught and fixed an old dispatch acknowledgement that initially suppressed that recovery.
