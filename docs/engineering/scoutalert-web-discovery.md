## Implemented path

An existing activation or reconciliation outbox event starts the finite scout workflow. The `scout-public-web-discovery-v1` Temporal patch adds a bounded public discovery phase before indexed matching. Activities run on `scout-web-discovery-v1`, separately from collection, assessment, research and email. A web outage falls back to existing indexed matching. The web phase can add up to roughly four minutes before matching. The `scout-lead-evidence-v1` patch adds a separate finite review phase of up to roughly three minutes (an in-flight bounded call may finish afterward). Source and mail queues continue independently.

`packages/core/src/discovery` owns lead, observation, capability, plan and repository contracts. `DiscoverWeb` advances one durable step through those contracts. With AI enabled, new cases use `public-intent-v3`: `PlanScoutSearch` separates explicit alternative professions from the public target, freezes focused query strategies, and selects permitted next actions using reviewed public evidence. Original target words must be preserved across at most three strategies; new professions and identifiers are rejected. The full confirmed brief remains authoritative in private matching, including AND requirements. This first model planner does not interpret the entire free-form goal or generate unrestricted synonyms.

Only target, category and remote preference enter public planning. Full goal, account identifiers, background, residence, compensation and private fit stay out of search and shared planner input. Targets resembling URLs, email addresses, long numeric identifiers or multiline text require a clearer public target. Historical `public-intent-v1` and `public-intent-v2` cases retain their fixed and deterministic-adaptive behavior. Disabled AI uses the deterministic policy; unavailable model planning falls back to the confirmed public target without weakening matching constraints.

`packages/adapters/src/discovery` owns Serper HTTP access, public source retrieval and PostgreSQL implementations. The API composes `ReadWebDiscovery` under the existing web-request and account-session guards. Next.js reads `/v1/discovery` on the server and presents real account-owned records at `/dashboard/discovery`. The fictional `/preview/discovery` experience remains separate. Existing scout editing, feedback and assessed recommendations continue at `/dashboard`.

## Admission, reuse and recovery

- A case freezes its scout revision, plan, provider capability/configuration, deadline and continuation intent. Paused or superseded scouts cannot admit more work or accept private associations.
- Public query keys include query semantics, provider configuration and a 30-minute time bucket. Source document keys include the canonical HTTPS URL, fetch-policy version and bucket. Shared operations contain no account IDs, private fit or private brief. Private case associations always bind owner and current revision.
- Short transactions reserve daily request counts and configured micro-dollar amounts before an external call. Per-provider concurrency and per-host leases bound work across worker instances. Reservations are retained after failure or ambiguity; they are admission accounting, not reconciled provider billing.
- Leases are fenced by token and expiry. A lost acknowledgement or expired lease does not trigger the same paid request again in the same bucket. A later run can retry under a new bucket and current budget. This deliberately favours bounded spending over blind retries.
- Search responses retain their windowed completeness and next-page hint. The adaptive policy can request page two when the preceding page adds at least two distinct promising results. Repeated result sets cannot justify further pagination. Model-guided cases select every document check after observing the portfolio. Historical deterministic-adaptive cases retain their initial half-allowance prefetch. Missing or inaccessible results never close earlier opportunities.
- Source candidates are recorded by hostname. They are not automatically registered as continuous sources yet. The existing fair scout reconciliation triggers subsequent finite searches, including when indexed matches already exist; adaptive exploration quotas and cohort fairness remain future work.

## Evidence and network boundaries

Search snippets are discovery hints. Incomplete social posts, service requests, offers and other pages remain leads without fabricated employer, pay, location or role fields. AI review now distinguishes a specific job/contract opening, client request, service offer, discussion/advice, directory, closed posting and unclear evidence. Search-excerpt verdicts are tentative: all extracted facts must remain unknown and snippets cannot enter the posting index or email ledger. Complete fetched source content can supply cited facts for private assessment; unknown company, location and publication dates remain null.

Public fetching permits HTTPS only, disallows credentials and non-default ports, validates all DNS answers with `ipaddr.js`, and pins an admitted address to the actual TLS connection while preserving hostname verification. Private, special-use and mapped addresses are rejected. Redirects are deliberately unresolved in this increment. Requests send no browser cookies or authenticated session. There is no browser rendering or challenge bypass.

The fetcher checks `robots.txt` first, honours disallow rules and bounded crawl delays, uses an identifying user agent, and limits robots/page bytes and total time. Inaccessible policies, long crawl delays, unsupported media and compressed responses without a supported decoding path remain explicit access gaps. This conservative behaviour may reduce coverage; it must not be hidden as a successful full crawl.

Fetched markup becomes inert text. Formal metadata is retained as a parsing hint, but no JSON-LD item bypasses demand review. A complete, untruncated, cited source classified as specific demand may enter the posting index when its short role phrase is present in evidence and any explicit deadline is still valid. Closed, conflicting-deadline, service-offer, discussion and directory results stay out. Native exact-URL listings are reused; broader entity resolution remains outstanding.

### Shared lead review and private matching

`ReviewDiscoveryLeads` performs at most one admitted model call per activity. Historical cases freeze at most 40 public inputs. Model-guided cases refresh a bounded source-only batch after each exploration round; the same immutable source version reuses its earlier review. They leave unchecked snippets explicitly unverified instead of spending a final classification batch before useful personal matching. Up to four short excerpts share a call; each complete source is reviewed separately. Inputs retain original provenance and distinguish source text from search hints. Text is bounded to 48,000 UTF-8 bytes for source input and 2,000 for an excerpt; truncated inputs remain leads. The structured request has a further 60,000-byte input ceiling, 4,000 output-token ceiling, 25-second timeout and no SDK retries.

Review keys include the public input fingerprint and model/schema/policy configuration. No account profile enters shared review. The provider selects passage IDs, which resolve to original text; citation, output-batch and fact checks run before publication. Arrangement and engagement have separate constrained schemas. Deterministic arrangement validation rejects payment or contract terms as proof of remote/hybrid/on-site work. Citation validity is not a guarantee of semantic correctness; independent classification evaluation remains required.

Reviews share the existing `intelligence_daily_budget` with extraction, research and personal fit, including the two-call global concurrency cap and $0.075 conservative reservation per attempt. The checked-in defaults remain 50 requests/$5 per UTC day. The user's local settings were subsequently raised to 5,000 AI attempts/$100 and 1,500 search attempts/$100 per UTC day. The worker configuration accepts 1–10,000 AI requests, while the independently configured USD ceiling remains authoritative. At $0.075 per admission, a $100 AI reservation ceiling admits at most 1,333 attempts even when the request setting is higher. These are current local settings, not changed checked-in defaults. A failed or ambiguous attempt retains its reservation. Transient failures may be retried once by a later run after five minutes; invalid evidence is terminal for that input. Expired or changed inputs cannot publish late model output. Ready reviews refresh unchanged public observations without another model call, and publication fingerprints remain stable across PostgreSQL JSON key ordering.

Short publication/coordination transactions lock the web source aggregates before scout/case/task/lead/posting state, consistently with matching and delivery. Network work runs outside transactions. These aggregate locks need contention measurement before high-volume rollout; no global-scale throughput claim is made.

Public extraction is reused by the existing intelligence repository; each owner's confirmed brief still receives a separate personal fit assessment. General web candidates cannot fall back to title-only recommendations when AI is unavailable. The private read model separates offers/discussions/directories/closed results, shows source versus excerpt review and citations, and reports budget/deadline deferrals. Classification alone is not a personal recommendation.

### Availability and eligible delivery

A web availability adapter reuses the exact current, complete, recently captured source plus its accepted demand review. It requires stated application instructions and retains the original source-observation timestamp. After fifteen minutes, an explicit deadline, a changed version, or inaccessible evidence, it cannot authorize mail. It does not make another unbudgeted network request; the discovery coordinator owns refresh and host pacing. This establishes recent actionable public evidence, not that a human confirmed a vacancy is still open or that the applicant is eligible.

All general-web jobs and client requests require that fresh evidence before an email, in addition to current private assessment, consent, version checks and the existing recipient delivery ledger. Verified prompt alerts retain their stricter supported-criteria and personal-declaration requirements. The live smoke used an ordinary digest with visible uncertainties. Observed application destinations can now be investigated under the normal document allowance, depth and network policy. Each captured page receives its own demand review. Public research can now reuse up to two recently captured application/employer pages actually linked from the posting. It investigates location, authorization, sponsorship, requirements and an explicit absolute deadline, records citations and role applicability, and retains unresolved outcomes. It cannot infer a person’s authorization. Role-specific contradictions stay conflicting; general employer policies cannot overwrite specific posting restrictions. A cited application deadline can close or shorten eligibility for delivery. Broader employer identity resolution, unrestricted multi-source synthesis and dedicated opportunity-change dispatch remain future work.

## Adaptive planning and linked-source investigation

New cases freeze a public target, remote preference, maximum of six total search operations, four adaptive actions, and investigation depth of two links. They retain the existing four-minute case deadline and configured total document cap (four by default). These are local operating envelopes, not permanent product-coverage restrictions. Each action is admitted against the same global daily/provider/host ledgers. Model-guided planning admits at most one structured model call per activity and shares the global AI reservation and concurrency limits with all existing analysis.

After admitted steps settle, `DiscoverWeb` first reviews newly captured sources, then refreshes the durable snapshot. The core `explorationChoices` policy supplies a bounded set of permitted source checks, observed links, useful query refinements and a stop action. The model returns only an index and concise practical explanation; it cannot invent URLs, raise limits or execute tools. Unreviewed snippets are labeled routing hints. Closed demand, offers and commentary cannot justify further source-link exploration. Historical deterministic cases use `planExploration` directly.

Source-link ties preserve page order. A source-access failure defers its host for the remainder of that case. Following an application or employer-policy anchor still requires a permitted source read, supporting quotations and applicable research before facts affect fit. Explicit unknowns remain unknown when sources cannot be read.

The HTML parser retains at most 80 unique visible HTTPS anchors, with bounded label text, and ignores base tags, navigation, scripts, forms and hidden nodes. The planner follows relevant anchors or a clearly labeled application link on a relevant listing; it does not invent destinations. The existing DNS, TLS, robots, host pacing and response-size restrictions apply at every hop. Source denial stays unresolved. Parent operation, exact action, depth and reason persist in `web_discovery_decisions`; each child remains independently reviewable evidence.

Adaptive append runs under the current-scout/case lock, recomputes permitted choices against durable history and rejects stale or invented decisions. A unique case/round key fences concurrent retries. Public operation keys preserve explicit field ordering across JSON storage, so another owner can reuse the same work while receiving only their own case associations. Frozen historical plans are not rewritten. The additive `20261001-worldwide-source-exploration` migration supplies the decision ledger and step depth.

The dashboard exposes a plain-language search trail, including stopping reasons. Selected steps and completed counts are distinguished: an action may have been planned but deferred at admission. Search excerpts, directory links and application destinations still need evidence review and private fit before they can become recommendations.

Public strategy/choice tasks use canonical immutable inputs, model/policy configuration and a six-hour reuse window. A private run/phase binding fixes the task across retries and time-bucket changes. Scout status/revision, case deadline, leases and the two-call global AI cap are checked before admission. Invalid decisions and uncertain failures do not trigger repeated paid calls; usage is retained when available, including rejected structured outputs. Ready plans are read from the frozen case rather than regenerated on every activity.

The additive `20261001-worldwide-strategy-reasoning` migration adds these shared tasks, private phase bindings and incremental review metadata. It has been applied locally. The model still chooses among bounded policies: learned query yield across runs, multilingual semantic planning, provider selection, a persistent crawl frontier, source registration and native social access remain open.

### Admission, continuation and efficiency

- Default maximum: 32 current monitored URLs per scout, configurable with `SCOUT_MONITOR_MAX_SOURCES` (1–256). All owners share each public URL's capture and review; fit stays private.
- Directories admit at most four new observed links **per captured observation, shared across subscribers and retries**, and at most two levels of automatic expansion. Candidates wait for independent page retrieval and cited review; a parent never supplies a child's facts. Other observed links remain in the persisted frontier for later checks.
- A link-destination change counts even when visible text is unchanged. Unchanged public text reuses its prior extraction; it does not fabricate a new observation time.
- Initial/changed-page revisit interval is 30 minutes. Unchanged pages back off through 60 minutes to a 24-hour maximum. Access failures have explicit reasons and bounded retry delays; blocked pages and repeatedly failed probes retire. A successfully fetched probe waits for review and can retry later if review capacity was unavailable.
- A page needs an active current scout interest before another fetch is admitted. Pause/edit immediately invalidates old private interests. Public work may continue for another interested active scout; that never authorizes publishing to the paused or superseded scout.
- Immutable check receipts and pending subscriber updates commit together. Dispatch coalesces observations into at most four pages per current scout run and 50 idle scouts per batch, using the existing outbox. These runs skip a new paid search portfolio, then use existing review, private assessment, evidence freshness and delivery gates. Broad discovery keeps its own reconciliation timestamp, so successful monitoring does not switch exploration off.
- Budget exhaustion waits until the UTC reset unless the worker is reloaded with a higher document allowance. Budget-only holds become eligible as soon as the current day's retained usage falls below that configured limit; failure backoff, host pacing, global concurrency and current scout-interest checks still apply. Reservations are never cleared or refunded to force a run. Slow hosts yield their place in the due queue. No full-domain scraping, executable connector generation or private-platform access was added.

Deploy both additive `20261002-*` monitoring migrations before restarting the worker/API. The second migration fences shared per-capture expansion after a rollout review identified that separate subscribers could otherwise each enqueue four links. Already-admitted URLs remain subject to the original daily budget and source-interest ceiling. `SCOUT_MONITOR_ENABLED=false` disables monitor activity and learning; ordinary configured discovery continues.
